# Loopback API Security Model

How o8 decides whether an `/api/*` request is allowed. Implementation:
`src/middleware.ts` + `src/lib/auth/loopback-request.ts`. Deterministic
coverage: `tests/middleware-gate.test.ts` (run with `npm test`).

## Why this exists

The Next.js backend binds `0.0.0.0` so the mobile surface can reach it over
LAN/Tailscale. That means **every device on the network can open a TCP
connection** to the API — and the gated families can dispatch agents, approve
merges, read transcripts, and spend the operator's LLM keys. The middleware is
the only thing standing between a LAN device and that surface.

## The decision ladder

For any request to a gated prefix (see `GATED_PREFIXES` in `src/middleware.ts`),
in order:

1. **Worker-route bypass.** `/api/worker/*` and `/api/cloud/*` skip the gate
   entirely — workers run off-host by design and each handler verifies its own
   bearer token against the `worker_tokens` table / cloud-worker key files.
2. **Allowlist.** `ALLOWLIST_READ_ONLY` passes GET/HEAD only (setup wizard
   reads, VAPID public key, panel status). `ALLOWLIST_ANY_METHOD` passes the
   OAuth handshakes. Keep both lists minimal.
3. **Loopback trust** (`isTrustedLocalRequest`) — see tiers below.
4. **Bearer token fallback.** Non-loopback callers must present the ws-token
   (`~/.o8/ws-token`) as `Authorization: Bearer <token>` or `?token=`.
   Comparison is constant-time (`timingSafeEqual`).
5. Otherwise: `401`.

## Loopback trust tiers

### Tier 1 — socket truth (packaged builds, authoritative)

The bundled production server (`out/server/server.js`, generated by
`scripts/tauri-export.mjs`) wraps Node's `http.createServer` and stamps
**`x-o8-client-addr`** with `req.socket.remoteAddress` on every request —
*overwriting* anything the client sent. The header therefore carries the real
TCP peer address and cannot be spoofed by a direct connection.

When the header is present, it is the **only** signal consulted: loopback
address → trusted, anything else → fall through to the bearer-token check.
`Origin`, `Host`, and `sec-fetch-*` are all client-controlled, so they are
deliberately ignored once socket truth is available.

### Tier 2 — dev fallback (next dev / dev-bridge, best-effort)

The stock Next dev server doesn't stamp the header, so the gate falls back to
heuristics that keep curl/scripts/dev-browser friction-free:

- loopback `Origin` (or `tauri://localhost`)
- `sec-fetch-site: same-origin|none` **and** loopback Host
- no browser headers at all **and** loopback Host

A deliberate spoofer on the LAN can defeat Tier 2. That is the accepted
trade-off for dev ergonomics — packaged builds always have Tier 1.

## Token delivery to mobile clients

- The pairing QR encodes `{host, apiPort, wsPort, token}`.
- The copy-link path appends the token as a **URL fragment** (`/mobile#tk=…`).
  Fragments never hit the wire or server logs; `getMobileWsToken()`
  (`src/lib/mobile/ws-token-client.ts`) captures it into localStorage and
  scrubs the URL via `history.replaceState`.
- The `/mobile` layout embeds a ws-token `<meta>` tag **only when the request
  itself proved loopback** (`headersIndicateLoopback`), so a LAN fetch of the
  page HTML cannot harvest the token.

## Rules when adding routes

- New route family that touches agent/repo/operator state → add the prefix to
  `GATED_PREFIXES`, and update the API security section in `CLAUDE.md`.
- Need public access → GET-only under an `ALLOWLIST_READ_ONLY` entry, never a
  blanket bypass.
- Never read `Origin`/`Host` directly for trust decisions — go through
  `@/lib/auth/loopback-request` so socket truth keeps winning.
- Add a case to `tests/middleware-gate.test.ts` for any new allowlist entry or
  gated prefix.
