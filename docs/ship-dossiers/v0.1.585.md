# Ship Dossier — o8 v0.1.585

> Source document for the promo/ship video. o8 is **the governance layer for autonomous engineering teams**. Audience: build-in-public founders and developers. Numbers are used ONLY where measured; codenames and per-tier model names are never mentioned.

## 1. The headline

**v0.1.585 makes o8 dramatically faster — and gives it a complete status-motion design system.** A dedicated performance agent tore cold launch and idle CPU down to the root; alongside it, the agent-status dots became one coherent motion language on a single pixel canvas.

## 2. The speed story (the meat)

A standing performance hunt, run on the honest hardware — an Intel i7-10700K desktop, the app's actual performance floor ("it's fine on an M-series" was not accepted as a resolution). Every fix carries a measured before/after with median and spread; anything with >20% run-to-run spread was thrown out.

**Cold launch, attacked at the root.** The single largest item in a cold launch was a step that does no visible work at all: compiling every capability's URL patterns into regex automata on the main thread *before the window even exists* — 1665ms of a 4.3s launch. It was cut to **971ms** by merging four capabilities with byte-identical permission sets into one (24 patterns → 12; proven identical by an ACL-surface diff, no security surface changed). The Node sidecar — the phase the loading screen spins in front of — was spending its boot *compiling*, not running: a V8 bytecode compile cache took it from **1955ms → ~1063ms**, and a stray browser-automation library that loaded before the app could answer a request was made lazy. And the window itself was reordered to **paint before the bootstrap runs** — previously you clicked the icon and got no window at all until the entire boot finished; now the window is built as soon as ports resolve and the heavy work is handed to a worker thread.

**Idle tamed.** At rest, doing nothing, the app was burning roughly 11% of a CPU core. Root causes, one at a time:
- The status-dot animation drove a *paint* property (`background-position`), forcing WebKit to re-rasterize every dot every frame. Moved to a compositor-only transform: **idle WebKit CPU 9.5% → 2.2%** (19× cheaper for the dots), pixel-identical to within 0.001px, verified side-by-side in the running app.
- A worktree conflict scan ran a recursive disk walk every 5 seconds and threw the result away. First made cheap (**1974ms → 519ms** per tick), then made **event-driven** — it now runs only when a git ref, index, or working tree actually changes. Idle git work fell from **39% of a core → 0.87%**, a 45× reduction, while *noticing* a real change went from up-to-5-seconds to sub-second.
- Idle HTTP chatter dropped from **~37 requests/min → ~14/min**: a spec pane that polled the server every 4 seconds while nobody was looking at it now goes silent when hidden, and a live signal was wired where six surfaces had been forced to poll because a lifecycle event was being dropped on the floor.

**The 33-second freezes, eliminated.** Synchronous git calls sitting on the event loop were wedging the whole server; they were moved off the hot path.

**The honest part — the best build-in-public beat.** The performance agent's *first* boot numbers came from synthetic microbenchmarks, and when it finally built the app and read its own boot stamps on a quiet box, the running app contradicted them. It published a **CORRECTIONS** section retracting its own overstated claims — the login-shell probe it had called ~690ms was ~60ms in situ; a claimed −415ms saving was really ~100ms — and re-pointed the hunt at the real monsters the microbenchmarks had hidden. The lesson it kept repeating, and then had to eat: **measure the running app, not the source tree.** (It nearly shipped a fix for 139 CSS blur sites that don't exist at runtime — the glass is native macOS vibrancy; the live app has zero live backdrop-filter layers.) *Use the corrected numbers below, not the retracted first-pass ones.*

## 3. The design story

A complete status vocabulary, expressed on **one 3×3 pixel canvas** — every agent state is the same nine cells behaving differently, so the whole fleet reads as one system. It grew out of studying the *rules* behind the best loader systems rather than copying their looks: the canvas is law, rhythm defines state, sharp pixels beat soft bloom. 28 candidates were generated in a live motion lab and operator-curated down to five:

- **Drift** — idle. Cells wander gently, and each instance is **desynchronized** so a wall of idle agents never pulses in lockstep.
- **Breathe** — working. A calm, whole-canvas swell.
- **Hold-blink** — awaiting review. A held beat with a blink, signalling "waiting on you."
- **Gravity** — failed / rejected. The cells **fall with gravity, then reassemble** — a collapse-and-recover metaphor, rendered in a single brand orange (one orange across failed and rejected; the label carries the difference, not a second color).
- **Settle** — merged. The cells settle into place and go quiet.

All motion is compositor-only, so the vocabulary itself costs nothing at idle.

## 4. Also in this release

- **Repo-scoped workspace rail** — the branch-details rail is now scoped to its own tab's repo, ending cross-repo duplication in the rail.
- **Review-candidate motion lab** — bespoke awaiting-review loader candidates staged in the lab for operator review (the curation surface behind the status family).
- Misc fixes — a packaged browser-engine load failure now fails loudly and verifies the real path; assorted boot-ordering and instrumentation hardening.

## 5. Video beats (suggested shot list)

1. **Cold-launch stopwatch A/B** — old build vs new, side by side, window-appears-to-usable. Lead with "no window at all until boot finished" → window paints first.
2. **Activity Monitor idle CPU A/B** — WebKit process at rest: 9.5% → 2.2%. Let the number sit.
3. **The status dots at true dot-scale, then enlarged** — capture on the motion lab at `/preview/motion` (the ideal surface): show Drift/Breathe/Hold-blink/Gravity/Settle tiny, then blown up so the 3×3 canvas is legible.
4. **Gravity in slow motion** — the cells falling and reassembling, the one moment worth the enlargement.
5. **A sidebar full of live dots** — a wall of agents in Drift (visibly desynced, never pulsing together) with a few Breathe and one Gravity — the "one system" payoff.
6. **The corrections beat** — flash the retracted-vs-actual table on screen as the honesty moment: "we published our own corrections."
